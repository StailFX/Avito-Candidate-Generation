# Кандидатогенерация услуг Авито

Для каждого из 2452 запросов нужно выбрать 50 объявлений из корпуса
в 189 212 штук. Метрика — macro Recall@50: считается доля найденных
релевантных объявлений по каждому запросу, потом среднее.

Описание подхода, валидации и результатов — в `solution.ipynb`.
Ноутбук сохранён с выполненными ячейками, можно открыть и прочитать
без запуска.

## Подход

Решение работает в два этапа: сначала несколько источников собирают
пул из ~559 кандидатов, потом CatBoost выбирает 50.

Источники кандидатов:

- **BM25 и TF-IDF** — ловят точные слова, формы и опечатки.
- **multilingual-e5-small** — смысловой поиск. Исходная модель
  из HuggingFace, query-башня дополнительно обучена на парах
  «запрос → выбранное объявление». Document-башня заморожена,
  векторы корпуса пересчитывать не нужно.
- **История взаимодействий** — подсказывает вероятную категорию
  услуги и популярные объявления для похожих запросов.
- **География** — мягкий приоритет по локации, без жёсткого отсечения.

Ранжировщик — `CatBoostRanker` с `PairLogit`, 100 деревьев глубины 5,
66 признаков. Обученная модель лежит в `models/final_ranker.cbm`.
Веса дообученной query-башни — в `models/query_encoder_adapter/`.

## Воспроизведение `answer.csv`

### 1. Положите данные

Скопируйте три файла от организаторов в папку `data/`:

```
data/train.parquet
data/benchmark_queries.parquet
data/benchmark_items.parquet
```

### 2. Поставьте зависимости

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Запустите

```bash
cd src
python reproduce_answer.py
```

Скрипт делает всё сам:

1. Скачивает зафиксированную версию E5 из HuggingFace (если ещё нет).
2. Кодирует объявления и запросы (кешируется в `artifacts/reproduce/`).
3. Строит лексические индексы.
4. Применяет адаптер и ранжировщик.
5. Пишет `answer.csv` и проверяет SHA256.

Побайтовое совпадение гарантируется при тех же версиях библиотек
из `requirements.txt`. На CPU первый запуск занимает 40–60 минут
(основное время — кодирование 189k объявлений). Повторный запуск
с кешем — около 10 минут.

### Проверка формата отдельно

```bash
python src/validate_answer.py answer.csv --data data
```

## Что лежит в репозитории

```
├── solution.ipynb              — ход решения, графики, валидация
├── answer.csv                  — готовый ответ (2452 × 50)
├── requirements.txt
├── data/                       — сюда кладутся исходные parquet
├── models/
│   ├── final_ranker.cbm        — обученный CatBoost (70 КБ)
│   └── query_encoder_adapter/  — веса дообученной query-башни (81 МБ)
└── src/
    ├── reproduce_answer.py     — единый скрипт воспроизведения
    ├── retrieval.py            — текстовые индексы и признаки
    ├── semantic_adapter.py     — линейная адаптация E5
    ├── semantic_context.py     — контекстные сигналы из истории
    └── validate_answer.py      — проверка формата ответа
```

Базовая E5 скачивается из HuggingFace при первом запуске.
Исходные данные в репозиторий не включены.
