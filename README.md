# Тестовое: кандидатогенерация услуг Авито

Для каждого из 2 452 запросов нужно выбрать 50 объявлений из корпуса в 189 212 штук. Метрика — macro Recall@50 (доля найденных релевантных по каждому запросу, потом среднее).

**Результат:** [вписать macro Recall@50 на валидации]

Готовый ответ лежит в `answer.csv` (2452 × 50). Ход решения, валидация и графики — в `solution.ipynb`; он сохранён с выполненными ячейками, запускать не обязательно.

## Что сделал

Решение в два этапа: сначала несколько источников собирают пул из ~559 кандидатов на запрос, потом CatBoost выбирает из него 50.

Источники кандидатов:

- **BM25 и TF-IDF** — точные слова, формы, опечатки.
- **multilingual-e5-small** — поиск по смыслу. Запросы проходят через адаптер, обученный на парах «запрос → выбранное объявление». Документы кодируются исходной E5 без изменений, так что эмбеддинги корпуса после обучения пересчитывать не нужно.
- **История взаимодействий** — вероятная категория услуги и популярные объявления по похожим запросам.
- **География** — мягкий приоритет по локации, без жёсткого отсечения.

Ранжировщик — `CatBoostRanker` с `PairLogit`, 100 деревьев глубины 5, 66 признаков.

Внешние API ни при обучении, ни при предсказании не использовались.

## Как проверить

Быстро — проверить формат готового ответа (из корня репозитория):

```bash
python src/validate_answer.py answer.csv --data data
```

Полностью — воспроизвести `answer.csv` с нуля.

1. Положить `train.parquet`, `benchmark_queries.parquet` и `benchmark_items.parquet` в `data/` (в репозитории их нет).
2. Поставить зависимости:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```
3. Запустить:
   ```bash
   cd src
   python reproduce_answer.py
   ```

Скрипт скачает E5 с HuggingFace, закодирует корпус и запросы (кеш в `artifacts/reproduce/`), построит лексические индексы, применит адаптер и ранжировщик, запишет `answer.csv` и сверит SHA256. На CPU первый запуск занимает 40–60 минут (почти всё уходит на кодирование 189k объявлений), с кешем — около 10. Хеш должен совпасть при версиях библиотек из `requirements.txt`; на другом железе возможны мелкие расхождения.
